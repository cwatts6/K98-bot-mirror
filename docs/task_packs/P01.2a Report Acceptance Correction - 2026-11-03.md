# P01.2a report acceptance correction

Status: local correction and qualification; no new PR, promotion or deployment.
The operator authorized fixes, investigation of monitor/gateway delays, combined

## Defects and corrections

The accepted design required freezing independent diagnostics before incident
enumeration. The implementation did the reverse and reused an expired census
deadline for every provider, producing a valid but nearly empty partial ZIP.
Capture now precedes SQL. Cancellation/shutdown still stop collection; a census
budget expiry returns an explicit time-bound reason and preserves the frozen
components. The incident cursor remains at the original cutoff and `after=None`
when an unfinished incident archive was discarded. No second scan is started.

The ordinary report passed the entire monitor/startup/cache aggregate through a
depth-four serializer. Real monitor failure frames exceed that depth. Monitor
projection now accepts only named monitor fields, with depth eight, 32,768 visited
nodes, bounded strings/collections and a 12 KiB component budget. Other providers
retain depth four. Oversized history gets explicit omitted/trimmed fields; current
state, original failure and cycle checkpoints are retained when they fit. Ordinary
report providers are independently guarded and keep the established field names.
This narrow depth amendment is required to represent the existing monitor schema;
it does not authorize arbitrary object serialization or exception text.

The available authority identity was read from `legacy.client`, whereas the real
runtime exposes `legacy.recovery_client`. The validated deployment hash and its
source are now included. This hash is not the Bot Git SHA or provider health.
Short operation previews prefer current V2 evidence over legacy projections and
continue past oversized rows. Full archives preserve both, including first failure.
Manifest descriptors state schema, source, export time, counts and publication
watermarks; unavailable historical times/counts remain unknown. Diagnostic parts
carry the retained component's original capture metadata.

## Time and gateway investigation

Thirty seconds is a cooperative report-census budget, not a business-operation
deadline. Known configuration/startup/monitor activities taking two or more minutes
remain pending and owned. An entered native call can exceed this budget; collection
does not detach or forcibly terminate it. Raising it to two minutes would not fix
the coupling or nested-monitor serialization defects.

The supplied gateway warning reports 41.6 seconds behind at 22:38:31.662. Inspection
of the locally installed Pycord `KeepAliveHandler.ack()` shows this is heartbeat-send to
acknowledgement-processing latency, not a measured event-loop blocking interval.
Its implied send precedes the incident capture at 22:38:28.008. Concurrent MGE/Ark and
monitor activity is recorded, but proximity does not identify a blocking owner or
prove report causation. The supplied log has no event-loop stack/sample to establish
that cause. The distinct heartbeat-send-blocked warning/loop traceback is absent
from this excerpt. Network/gateway delay and delayed acknowledgement processing
cannot be distinguished by the supplied warning. Report UI uses owned thread offload; snapshot/serialization/SQL stay in
that worker. Monitor observation is a detached in-memory snapshot, not a probe.

A real barrier-held report worker was exercised for 125 seconds: the event loop
continued, a second report was refused, and a useful partial ZIP followed settlement.
Separate repeated-cancellation cases retain admission until physical settlement.
This controlled result is not a production gateway-root-cause claim. Natural
production lag attribution remains open; no restart, import/export, probe or
deliberate production failure is requested to manufacture evidence.

An additional CPU-heavy report test exposed a separate scheduling cost: five
18,000-row builds added 9.37 ms at p95 to local loop lag, above the 5 ms target.
The earlier builder also exceeded that target in the same harness (5.42 ms).
Neither measurement attributes the production heartbeat warning. A zero-duration
yield did not fix the local result. A positive one-microsecond sleep between
incident pages reduced the experimental p95 increase to 2.39 ms. The report
worker now includes that cooperative scheduling point; it retains its lease,
checks cancellation before another read, and keeps the original 30-second budget.
The sleep is a scheduling request, not a promise of microsecond timer precision.
Failed measurements are retained; final-source cost and loop qualification must
pass before readiness is claimed.

  programme obligations retain their existing owners. This correction does not
  close those packages or identify an unknown historical SQL holder.
