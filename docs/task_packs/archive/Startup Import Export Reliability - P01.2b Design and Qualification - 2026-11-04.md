## Scope summary

Provide a bounded account of an authorized startup attempt before Python or an incarnation journal exists, then correlate it with normal issuer evidence. Make the safe projection available through both the existing recovery download and an installed operator export when the bot is absent. It must explain missing executables, gate/custody/policy refusal, immediate issuer failure, observed exit and unknown handoff without starting another issuer or changing an original business result.

The main design constraint is the short-lived scheduled task. A permanent supervisor inside that task would conflict with the updater's requirement that the disabled predecessor task have zero instances. The original proposal uses a separately owned, release-pinned native observer while the wrapper remains the sole issuer launch site. E72 rejects the sole-reader redirected-stderr transport: observer loss changes the child's result. The observer must never start, restart, terminate, adopt or release application work. The original architecture below is retained for review, not approved for integration after this failure.

No new Discord command, SQL object, SQL query, provider action, recovery policy, activation flag or general logging redesign is proposed. The proposal changes the protected launch package and therefore needs an exact updater upgrade and gate transition, not just Python application compatibility.

## Architecture direction

### Original launch-observation proposal - suspended by E72

1. Promote the reviewed gate to a versioned, repository-owned template with fixed executable structure and a separately validated binding record. Install it through an exact predecessor-to-successor gate transition. `release_seed` remains a binding generator; it may not patch arbitrary gate behavior or infer trusted code from observed bytes.
2. After trusted gate/capture-code admission, allocate a diagnostic attempt UUID. Record requested origin/release reference if supplied by an authenticated existing start intent. For manual/scheduled starts lacking an authenticated initiator, record the known task/system origin and the precise missing-human reason. Never attribute the last Discord user.
3. Prepare an optional observer before issuer creation. Use a hidden Desktop PowerShell 5.1 host with a pinned, fully loaded native helper; no Python, bot imports, provider connection or lazy loading from live source. Bind its IPC to the same administrative identity, attempt nonce and native parent identity. It has no interface that accepts a command, executable or request to spawn an issuer.
4. The wrapper performs its existing readiness policy and invokes the issuer once. A narrow native helper replaces only process creation/handle plumbing needed for fixed argv and capture. Duplicate the actual process handle to the observer, rather than rediscovering it by PID. Restrict inherited handles to the intended stderr endpoint; prevent role children inheriting that pipe and holding EOF indefinitely.
5. No capture failure causes another process start. If optional observer setup fails before spawn, the single original launch can proceed with its existing stream handling and explicit capture-unavailable status. Once any issuer creation was attempted, an ambiguous result or lost acknowledgement never enters another launch path. Diagnostics do not expand the existing authorized start policy.
6. The scheduled wrapper returns with its original spawn/readiness outcome after the bounded observation handoff. The observer owns the stderr drain and retained process handle independently. It records issuer exit only from that handle's signalled state and native exit result. Cancellation of the requesting UI/shell cannot terminate application jobs or manufacture settlement.
7. The observer lives in the immutable release package, not a mutable updater or application directory. It must load all code before handoff. Normal issuer exit ends its drain, publication and handles; there is no supervisor restart loop. No timer kills the issuer. If the observer itself dies, its last snapshot remains incomplete; later exports must not infer its missing observations.

**Feasibility stop:** a redirected pipe can affect a child if its reader stalls or dies. An async callback alone does not solve this. Before integrating this architecture, native tests must demonstrate continued drain/discard under full queues, classifier/writer stalls and reader exceptions, and preserve the issuer's original outcome under observer-process loss and broken-pipe/flush cases. No `WaitForExit` before draining. No `ReadToEnd` accumulation. No PowerShell event callback requiring the blocked parent runspace. If observer death can block the child or change its result, this design is not accepted: revise the transport/lifecycle within P01.2b and return the concrete alternative for review. Do not claim those cases unavailable and defer the defect to P05.

The observer's file worker is separately bounded and cannot hold application locks or mandatory receipts. Any entered I/O remains visibly owned until settlement; a timeout is not proof of worker exit. Keep code and output outside replaceable live source, so an incomplete optional publication does not silently become an extra business-drain authority. Qualification must account for all observer handles/processes after normal exit and exceptional shutdown.

The existing `process_snapshot` rejects an exited process. Immediate-exit evidence therefore needs a narrow retained-handle observation that reads native creation/exit times and exit status after signalling; it cannot simply reuse the live-token snapshot and call failure an unknown PID. Keep the live authentication checks unchanged, and distinguish identity observed before exit from token/image details that could not be obtained.

### Capture, redaction and persistence

The native drain copies fixed byte chunks to a bounded, nonblocking classifier queue and immediately resumes reading. Queue saturation discards classification input while continuing drain and counting loss. Classifier and publisher cannot call back into launch admission. Exception handlers preserve original exceptions/results and use bounded local counters, not recursive logging.

Do not persist raw stderr. Interpret only code-owned stage markers, allowlisted exception classes and module/frame labels; replace every unrecognized message/path/value with a fixed redaction marker. Handle split UTF-8, invalid sequences, oversized lines, multiline secrets and control characters incrementally. Oversized lines enter discard-until-delimiter mode without accumulating the line. Treat stderr-derived classification as observed text, not authenticated policy failure or business outcome. Python's explicit stage event has separate provenance.

Keep the existing operator redactor as a second defense in Python projections; it is not a pre-Python capture dependency. Share redaction fixtures across native and Python implementations. Generic exception names are sanitized to a fixed fallback when outside the enum. Raw source lines, arguments, environment, SQL text, credentials, tokens and input contents never enter the safe record.

Use a new diagnostics-only namespace under the protected S11 root, with explicit role-specific custody. Proposed logical locations are `diagnostics/startup-v1/private`, `safe`, and `exports`; exact native paths must be sealed from the installed binding inventory. Private metadata/publisher state permits SYSTEM/Administrators only. The safe projection grants the application SID read access only, never write/replace/owner rights. The same Windows user has elevated and unelevated tokens: do not accidentally grant the user SID read access to private objects and call that privileged isolation.

Publish complete bounded safe generations atomically, using fresh objects with ACLs established at creation. Validate parent/object custody, reparse/hardlink/stream/metadata conditions and retain the previous valid snapshot through an interrupted replacement. No ACL change to existing business history, raw artifacts or application data. Optional diagnostics are explicitly not authoritative restart or replay state.

Existing `_attributes(..., application_read=False)` supplies the relevant native custody concept. Existing `write_new_protected` and `K98-SourceUpdate.ps1:New-Acl` default to application read, so neither may be reused unchanged for private launch records. Application `file_utils` atomic writes are unsuitable for creating administrator-only objects. The installer's `InvokeBoundedWorker` provides useful fixed-size read examples but kills its child on output/time limits; it must not be reused as issuer supervision.

### Record schema and evidence quality

Use separate `startup-launch-observation/1` and `startup-launch-projection/1` schemas. Keep existing incarnation, termination, deployment, operation-observations/1 and /2 schemas unchanged. Every nullable observation uses a value plus quality (`observed`, `unavailable`, `not_applicable`), fixed reason and observation UTC. Unknown is not encoded as zero or an empty successful list.

| Group | Required fields |
| --- | --- |
| Envelope / D01 | schema; diagnostic attempt UUID; monotonically increasing record sequence; phase; observed UTC; original authenticated release/start reference if available; diagnostic-only authority; source generation |
| Actor / D02 | initiating kind/identity/quality; executing SID and elevation; host identity; origin (`scheduled`, `manual`, `deployment`, `drain_only`, `unknown`); requester distinct from executor; wrapper/observer/issuer PID and creation FILETIME |
| Binding / D01-D03 | gate, wrapper, issuer, interpreter and policy SHA256; canonical source-inventory digest; expected versus observed binding; native-handle observation source; logical launch reference distinct from issuer role ownership |
| Timing / D04 | readiness start/end; spawn attempted/returned UTC; issuer created UTC/FILETIME; exit observed UTC; native exit time when obtainable; inclusive phase durations; observation budget and physical settlement separately |
| Outcome / D05 | launch not entered / spawn attempted / spawned / spawn unknown; wrapper result; issuer exit observed/unknown; journal correlation pending/matched/conflicting; existing receipt references only; pair/SQL/provider outcome explicitly not certified |
| Retained milestones | first entry, first meaningful failure, cancellation/deadline observation, journal handoff and terminal exit; later success cannot overwrite first failure |
| Loss / D06 | bytes drained, classified, discarded, invalid encoding, oversized lines, queue drops, records refused/evicted, capture/publish/read failures; collection and publication timestamps/watermarks; current process counters versus restored historical counters |
| Export | safe projection digest/bytes, producer schema, captured/exported UTC, retained/selected/omitted counts or explicit unknown, retention cutoff, collector identity and source binding quality |

Correlate a journal only when its policy hash and exact issuer PID/creation identity match the attempt and its publication chain validates. Preserve both records if journal appears before exit, after exit, after a lost notification, or after the observer stopped. Correlation is an additional observation, never a rewrite of the original attempt. Never synthesize an incarnation to fill a missing journal.

For launch mutex ownership, report the requester and acquired mutex scope separately. A collision must not label the requester as holder. Capture application-owned holder identity at acquisition/release if available through the existing owner, and test known-holder overlap. Native SQL holder detail remains P02; entering the issuer's SQL phase does not make launcher stderr evidence a holder census.

### Online and offline consumers

Add `early-startup.jsonl` to the existing bundle schema registry and assembly order. Read only the authenticated safe projection, off the interaction loop, before incident collection. Unavailable, stale, malformed or wrong-scope early evidence gets its own descriptor and does not suppress startup/operation/incident data. Keep `RecoveryService` and the existing download view's authorization, physical lease, final-send revalidation, cutoff/cursor and retry behavior. Reuse their generic component continuation. Confirm ordinary/ZIP projections tell the same story while honestly retaining different observation times.

Add an explicit passive `-ExportStartupEvidence` branch to installed `Update-K98.ps1`, mutually exclusive with prepare/deploy. It invokes a pinned PowerShell export adapter before the current no-active-update early return, and validates installed tool inventory/custody first. `-Status` may show a small safe coverage summary; it must remain read-only. No automatic export, Git fetch, prepare, reconciliation, native process adoption or provider health request follows from status.

Offline export validates the current Windows SID/elevation, host, scope and fixed source namespace. It writes only to the protected export directory. It accepts a server-issued collection ID/continuation identity, not arbitrary source/destination paths. Freeze complete safe bytes, counts, hashes and cursor atomically; index the exact ordered selected attempts. Retrying an uncertain export returns the same bytes/generation/successor without rereading or extending expiry. Persist two-generation metadata so the same administrator can resume after a process restart within the fixed expiry. Revalidate access and custody on every retry. Uncommitted partial files are never returned as successful parts; retain them within quota. Expired data requires a newly labelled collection.

Hashing alone does not authenticate caller-supplied evidence. Trust comes from installed code/bindings, native access checks and protected producer custody. The unelevated bot can only read the safe copy; it cannot request elevated export or select paths. Saved exported artifacts remain diagnostic and grant no recovery authority.
