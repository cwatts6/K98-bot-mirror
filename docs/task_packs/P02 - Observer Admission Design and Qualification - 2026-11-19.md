# P02 observer/admission design decision and qualification plan

Date: 19 November 2026. Status: **recommended design for review; not implemented or qualified**.

## Decision and scope

Recommend **coherently versioned, optimistic catalogue observation**, with bounded coalescing and reuse inside one admission. Observers must stop owning `K98:maintenance-schema:v1`; existing producer, recovery-reader and maintenance ownership stays in place. SQL must provide a complete change-detection contract before this change can be enabled. An observer accepts a result only when its entire observation is bracketed by the same generation and no relevant writer is active. Otherwise it discards the candidate and returns a typed deferred result. Writers do not wait for an observer's application lock.

This is a Bot **and SQL** correction to D2/D3, with D4 transition work and D5 changed-path qualification. It is not a permission to change the running system. The selected design still has explicit native feasibility gates: catalogue reads can take engine locks even without an application lock; incomplete invalidation would be unsafe. If either gate fails, stop and revise the design. Do not call a smaller lock conflict, a safe refusal, or a passing model coexistence acceptance.

The intended outcome is fewer self-generated refusals, delays and incidents while preserving business correctness, mandatory custody, exact ownership and recoverability. Full current validation remains mandatory at an admission that needs it. Passive status does not initiate it. There is no new monitoring daemon, SQL notification subscription, provider probe, general event bus, global isolation change or revived P01.2b instrumentation.

The [19 November reconciliation](P02%20-%20D7%20Reconciliation%20and%20Remaining%20Scope%20-%202026-11-19.md) retains the status and historical execution record. The operator's local-testing correction below supersedes its cumulative-quota language. This design adds requirements; it does not overwrite its bytes or any original receipt. D7 remains **1/4**. E1 stays closed; E2 stays failed/not_applied; a future new decision is distinct from replay. Keep MINI_AMD running. This phase performs local source/evidence review and documentation only.

## Proposed coherence protocol

### SQL contract (new; names are design names, not existing objects)

Use one monotonic `bigint` **NO CYCLE** sequence (`dbo.P02ObservationGeneration`) and one distinct writer-presence application resource (`K98:catalogue-mutation:v1`). A participating mutation takes **Shared** ownership of this resource before its first relevant change and advances the sequence before making that change. Transaction-owned marker lifetime covers the real transaction; autocommit maintenance needs a session-owned marker across its multi-statement work, with explicit acknowledged release. Markers are compatible with one another. Observers never acquire this resource or M.

The sequence is a change counter, not a business receipt or an equality-to-time test. Gaps, failed attempts and rollback consume values and conservatively invalidate a read. Do not subtract generations to infer operations, reset the counter, cycle it, or infer completion from its value. Missing/exhausted/recreated/altered sequence or unsupported marker contract closes admission for current validation; it cannot silently fall back to the old observer or a stale result.

Microsoft documents that sequence allocation survives transaction rollback and that `sys.sequences.current_value` is the last value obligated. Native qualification must establish the actual installed engine/driver representation, initial value, caching/restart behaviour, and readable identity under the application principal. The protected installation must consume and receipt an initial sequence value before any baseline can be accepted; the first participating mutation must produce a strictly greater value. Otherwise the never-used sequence's reported starting value could equal its first allocation and conceal that first change. Missing bootstrap evidence closes admission. Test that first-change case explicitly, as well as later gaps. [Sequence semantics](https://learn.microsoft.com/en-us/sql/relational-databases/sequence-numbers/sequence-numbers?view=sql-server-ver17), [catalogue representation](https://learn.microsoft.com/en-us/sql/relational-databases/system-catalog-views/sys-sequences-transact-sql?view=sql-server-ver17).

Writer-presence inspection uses `APPLOCK_TEST` for Exclusive grantability with Session ownership on a dedicated, unowned observer session. It tests compatibility **without acquiring** the lock. It returns `smallint`, not a Boolean contract to guess from a fake cursor. Calls on a borrowed connection must first prove it owns neither Session nor Transaction marker; branch on actual `@@TRANCOUNT` before querying Transaction-owned lock state. Do not rely on same-owner upgrade semantics to hide an active writer. [APPLOCK_TEST contract](https://learn.microsoft.com/en-us/sql/t-sql/functions/applock-test-transact-sql?view=sql-server-ver17).

The implementation manifest must cover:

1. Root publication/report/configuration/maintenance paths, taking the Shared marker before relevant DML/DDL; transaction markers end only with physical transaction completion. Acquisition is zero wait, with exact return codes and unknown-ACK custody. Do not introduce an observer Exclusive acquisition on this resource.
2. A database DDL invalidator covering application metadata, dependencies, synonyms, types, indexes, permissions/roles/signatures and database triggers. It advances the generation in the DDL transaction and keeps a transaction marker until completion. Direct supported DDL cannot evade invalidation. Test actual events, including procedure-based DDL; event-group names are not coverage proof. [DDL event catalogue](https://learn.microsoft.com/en-us/sql/relational-databases/triggers/ddl-event-groups?view=sql-server-ver17).
3. Statement-level lifecycle invalidation on `KVKFinalReportHeader`, `MaintenanceKvkWork`, and the `kvk_output` row of `MaintenanceWork`, including direct calls, early unknown transitions and failure recording. Avoid per-row counters and unrelated audit-table triggers. `TRUNCATE`, disabling triggers, bulk options and DDL replacement require explicit coverage or refusal; an INSERT/UPDATE/DELETE trigger alone is incomplete.
4. A small fixed reader procedure returning sequence identity/definition, generation and writer-presence result. It performs no increment, mutation, business guard acquisition or retry. Read `g1`, inspect writer presence, read `g2`; only equal values with no writer form a boundary token. The actual statement ordering must be explicit, not dependent on expression evaluation order.
5. Contract-health checks for the exact sequence, invalidators, enabled state, principal and permissions. An attacker with administrative control is not the intended trust boundary, but accidental trigger disable, missing enrollment or metadata drift must refuse. Database/server permission changes are not all database DDL events: effective permissions are freshly checked on the actual consuming connection; do not cache them behind a database-only generation.

An AFTER DDL/DML trigger is not by itself proof of a pre-change marker. Normal roots establish the marker first. For direct statement coverage, native cases must show that no other READ COMMITTED catalogue/lifecycle reader can accept partially visible changes before the invalidator runs. If this premise fails for any supported event, add an enforced pre-entry wrapper for that event or reject the design for that caller. Do not claim universal DDL coherence from a trigger's existence.

This contract is functional correctness infrastructure, so its failure is a real admission/integrity failure. Optional diagnostic emission remains best effort. Keep the new functional cost explicit; a trigger failure must not be misreported as an observer busy result or a committed business outcome.

An offline abstract interleaving challenge enumerated 495 one-writer schedules and 900,900 two-writer schedules: zero accepted mixed results; a missing-invalidation negative control did accept a mixed result. This checks the proposed ordering under explicit assumptions of a strictly advancing counter, pre-change marker and physical-completion lifetime. It does not execute the real helper or SQL, prove trigger visibility, validate native values, measure engine locks or establish useful worker progress. The script and receipt are retained with this design's private validation artifacts. No native SQL test was run.

### Bot observation and reuse

1. Select the connection factory once; preserve existing principal, login/statement/row-lock policies. Require READ COMMITTED and the supported actual transaction state; never commit/rollback or change isolation on a borrowed producer cursor to make a probe pass.
2. Read a complete boundary token. An active writer yields `deferred_active_writer`, closes the owned observer connection, and performs no full catalogue scan. Missing/invalid contract, permission failure and unknown cleanup are different outcomes.
3. Collect the **complete existing** application metadata, identity, effective-permission and maintenance-lifecycle categories. Preserve raw rows before canonicalisation. Keep the exact two-index projection and full comparator; the new proof format states generation/contract identity instead of falsely claiming `exclusive_schema_observation`.
4. Between bounded metadata batches, recheck the generation/presence token. On change, stop dispatching reads, discard the candidate and clean up. An already executing ODBC call remains physically owned until it finishes or cleanup is known; cancelling an awaiter is not cancellation of SQL.
5. After collection, repeat the complete boundary token and contract-health checks. Accept only the same sequence incarnation/definition and generation, no relevant writer at both boundaries, correct target/principal, and successful existing comparisons. Publish acceptance only after cleanup and late identity/startup checks.
6. Coalesce duplicate requests for the same admission/expected-contract key in one existing owned-work operation. At most one active full observation and one waiting request per runtime; additional callers receive a bounded pending result. Independent processes remain correct through SQL generation checks; no shared in-memory lock is claimed across them.
7. Reuse only metadata for the same operation/claim/fence/version, expected contract and configuration digests, process incarnation, connection lineage and unchanged generation. At actual business cursor entry, obtain a fresh boundary token and actual permissions/headroom/session checks. Reuse ends on producer entry, any mutation/change, source/config/registration change, disconnect, cancellation, unknown cleanup or process restart. No persisted success cache or timer-based freshness exception.
8. Observation success is a point-in-time schema/admission fact, never ownership or business completion. Existing action-time row locks/CAS, global producer guards, captures, provider receipts and atomic checkpoints remain mandatory.

Startup and updater use the same implementation and proof format. The updater still waits for the exact successor's initial admission outcome. It may consume that immutable observation within its recorded identity/generation validity, but must revalidate current bindings; a startup success marker alone is insufficient. The standalone verifier must not silently import the live Bot's older helper.

### Progress and bounded rescheduling

An observer yields to mutation; it must not make the producer retry. Use an existing same-process completion callback to schedule one new observation after acknowledged completion. Across processes, allow at most three cheap boundary-token checks, no faster than one second apart and inside the existing overall deadline. They hold no SQL connection across the wait. Only a new quiet boundary can admit the one replacement full observation. This is explicit read scheduling after a detected change, not replay of a business operation or a retry after unknown cleanup. There are at most two full observations per logical verification/admission deadline; both share the same budget.

A persistent writer or repeated changes may exhaust the observer budget. Return deferred with last successful evidence marked historical, not verified-current. Do not create an incident on each poll, advance an incident revision for elapsed time, or suppress a real mismatch. Ordinary controlled contention must settle automatically in the qualification schedule, with zero operator actions. Permanent mismatch, corrupt proof and uncertain custody remain actionable through existing incident policy.

## Measurable cost contracts

These are proposed acceptance maxima, not measured candidate results or permission to increase existing limits. Measure execute, fetch, scheduling, lock hold, producer transaction/commit, and cleanup separately. Report cold/warm distribution, median, p95 and maximum, statement counts and unsuccessful attempts.

| Boundary | Required limit and interpretation |
| --- | --- |
| SQL policies | Preserve 5 s login, 15 s ordinary statements, 1,000 ms metadata row-lock budget, 15 s coordination horizon and zero-wait producer application-lock calls. Recovery stays 3 s/zero row-lock wait. Existing explicit import/report/maintenance overrides retain their original operation-specific scope. |
| Standalone full verification | Existing 45 s observation budget and 256 normal statement ceiling shared by all contracts/connections/attempts; 3 s driver statement cap and zero row-lock wait. No budget reset on reschedule or cache miss. |

| Catalogue batches | Maximum 250 ms measured execute-plus-consumption per batch in overlap cases, to leave margin against a 1 s producer row-lock budget. In-process reuse reduces duplicate scans; generation checks avoid scanning during a known writer. Neither is a measured speedup yet. If complete batching/invalidation cannot satisfy the cost contract, reject the implementation before rollout. Do not raise the budgets, weaken comparison or postpone the required correction to P05.
