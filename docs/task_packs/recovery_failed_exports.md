# Guided failed-export recovery

## Required scope

Recover the retained failed export with its original input, creation time,
configuration and recorded fault visible before the admin decides. A missing
historical fault or original upload name stays explicitly unavailable. Avoid
mandatory technical pagination. Keep all other P0b recovery paths in scope.

## First focused path: obsolete output

Offer **Retire failed export** only after authenticated configuration history,
exact job and stream ownership, full private request/event membership, positive
child closure and no dispatched mutation all verify. Failed reads do not imply
failed writes. No attempts, held resources or requested retry may remain.

The admin confirms that this dated output is obsolete. Persist a private decision
and an exact SQL marker, then independently read both back before closing the
incident. Preserve failed job history, original streams and input. This performs
no import replay, provider write, resource release or deletion and certifies no
spreadsheet delivery. The same decision must reconcile after a lost reply or
restart. Changed evidence or conflicting decisions remain open.

## Acceptance and verification

- Concise original-input/configuration/fault summary and explicit retirement effect.
- No action for missing/corrupt private evidence, unknown writes, held access,
  foreign account/storage, changed membership or stale review.
- Confirmation uses the existing admin-only, scoped durable action workflow.
- Independent private receipt and SQL readback; duplicate clicks cannot replay.
- Complete report includes original identity and verified disposition.
- Disposable SQL checks use authoritative table contracts and temporary objects.
- Authority composition and installed updater packaging must be validated before
  release; passing service tests alone is not deployment readiness.

## Mandatory remaining paths

Still-needed failed output requires retained-input verification and guided safe
continuation; it must never be retired simply to reduce incident counts. Unknown
writes require the replacement/publication workflow. Missing private evidence,
genuine configuration drift, producer/rollover recovery and all other P0b cases
remain required delivery scope. This first path does not complete that scope.
